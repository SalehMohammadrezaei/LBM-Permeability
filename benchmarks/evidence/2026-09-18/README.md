# Executed validation evidence

These selected records preserve the completed workstation campaign in Git.
`manifest.json` records original local paths and SHA256 checksums of copied files.
`environment_summary.json` retains hardware, dependency and actual CUDA probe
details, excluding unrelated process listings and local working-tree output.

Start with `followup_summary.json`, `verification/comparisons.json`,
`case_inventory.csv` and `excluded_results.json`. The accepted standard and
half-force tensors retain raw signed values, per-load settings and convergence
histories under `long_rock/tensor_force_*/result.json`. Test XML includes the
initial failures as well as final source and installed-wheel checks. None of the
historical outputs have been relabelled as tests of a later Git commit.

The baseline was c1a195b62a9e519dbfeb23f2c764da1f2d14fad8 plus the owner's
uncommitted pressure-wall patch. Runs recorded package source hashes; final
installed-wheel hash records identify the tested package files. The only package
change after the accepted tensor campaign was the CLI missing-file error handler.

The complete local campaign remains at `results/2026-09-18-pilot/`. Downloaded
volumes, generated NPZ fields, plots, build products and archives are excluded
from Git. Dataset metadata and checksums are included; reproduction commands
are in `docs/benchmark_reproduction.md`. Historical command paths refer to the
original workstation. Repeats must use fresh output directories.

Numerical limits remain: experimental GPU-only 2D pressure mode, unqualified
weak-force float32 rock runs, percent-level voxel-surface error in oblique 3D
channels, finite-ROI local thickness, unmatched DRP-29 reference conditions, and
no 500³ allocation because the memory gate failed. This is technical evidence,
not a manuscript or a claim of independent rock-reference validation.
